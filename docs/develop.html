What OpenStudio SI core offers

The openstudio-si host plugin coordinates OpenStudio projects. Specialist plugins can build on these services while owning their own skills and scripts.

Orchestration and providers
Route requests to an appropriate workflow or modeling provider, including NLR OpenStudio-MCP when configured and compatible.
Workflow state and artifacts
Track sessions, model lineage, assumptions, and outputs across a multi-step modeling task.
Runtime and readiness
Set up and diagnose the core runtime. Plugin doctor checks declared prerequisites and reports which capabilities have enough evidence to use.
Simulation and results
Run simulations, collect artifacts, and query results through the core MCP runtime.

Declare what your plugin uses. HVAC Modeler owns HVAC workflows and requires a compatible core installation. Local HVAC inspection and edits can check core on disk. Simulation and results use the live core runtime. The OSM example below has a single runtime dependency, OpenStudio SDK 3.11.0, and can run independently.

The PyPI extra openstudio-si[plugin-dev] installs the developer CLI. Installing and enabling the core host plugin is a separate step for users of capabilities that depend on it. See installation options.

1. Create the project

Use Python 3.13 on a platform supported by the OpenStudio wheel. Run these commands in Bash or Zsh from the directory that will hold the new repository. The bootstrap environment stays in a temporary directory.

bootstrap="$(mktemp -d)"
python3.13 -m venv "$bootstrap"
"$bootstrap/bin/python" -m pip install 'openstudio-si[plugin-dev]==0.5.1'
"$bootstrap/bin/openstudio-si" plugin init ./osm-model-summary \
  --id osm-model-summary --name "OSM Model Summary" \
  --owner my-lab --maintainer "Your Name" --license MIT
cd osm-model-summary
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install 'openstudio-si[plugin-dev]==0.5.1'

Choose your own owner ID, maintainer and approved license. The template provides the source manifest, starter skill, evaluation examples, and GitHub Actions configuration stubs.

2. Add the summary skill

Rename plugin/skills/osm-model-summary to plugin/skills/summarize-osm. Add the skill instructions and bundled Python script from the full OSM walkthrough. The script reads an .osm file and reports stories, spaces, zones, and air and plant loops without saving or simulating the model.

In plugin/openstudio-si-plugin.yaml, keep your ownership and release version, declare OpenStudio 3.11.0 as a required Python distribution, and add the read-only summary capability. Copy the manifest example.

3. Verify and export

Replace the starter evaluation examples with the two-zone fixture and matching case. Run the script directly and confirm one story, two spaces, two thermal zones, zero air and plant loops, and unchanged input bytes.

openstudio-si plugin check-project .
mkdir -p dist
openstudio-si plugin export ./plugin --host all --output ./dist/plugin \
  > dist/export-report.json
openstudio-si plugin check-hosts dist/export-report.json

Confirm each export has one skill and zero MCP servers. The host check needs both CLIs. Load the appropriate export in your host and ask it to summarize the fixture. You can run an optional local agent evaluation. LLM scores are advisory and stay outside release CI.

4. Submit a release

  1. Push the project to your own public GitHub repository. Configure the template's workflows with openstudio-si plugin configure-ci using a reviewed harness commit SHA and an exact published tooling version.
  2. Ask the marketplace maintainers to register your plugin ID, source repository, manifest owner, and plugin path.
  3. Run openstudio-si plugin check-project . --require-tracked locally before tagging. Publish a stable GitHub release such as v0.1.0 matching your manifest. The release workflow attaches release.json and both host archives.
  4. Your repository publishes the release assets with its own GitHub permissions. Once the marketplace importer is enabled and your plugin is enrolled, central polling verifies the release and prepares a PR for maintainer review.

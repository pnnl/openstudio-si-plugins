OpenStudio SI developer documentation

Develop an OpenStudio SI plugin

Build and release skills, scripts, and MCP servers for Claude Code and Codex. This guide uses OpenStudio SI 0.5.1 and includes the CLI reference, schemas, and a complete worked example.

Quickstart

Use Python 3.10 or newer with a compatible OpenStudio SDK 3.11.0 wheel. The contributor CI uses Python 3.13. On Windows x64, the SDK publishes wheels for CPython 3.10 through 3.13 within the supported range. Run these commands in Bash or Zsh from the directory where you want the project. If needed, replace python3 with the command for your chosen interpreter. The bootstrap environment lives in a temporary directory and the project gets its own .venv.

python3 --version
bootstrap="$(mktemp -d)"
python3 -m venv "$bootstrap"
"$bootstrap/bin/python" -m pip install 'openstudio-si[plugin-dev]==0.5.1'
"$bootstrap/bin/openstudio-si" plugin init ./osm-model-summary --id osm-model-summary \
  --name "OSM Model Summary" --owner my-lab --maintainer "Your Name" --license MIT
cd osm-model-summary
python3 -m venv .venv
source .venv/bin/activate
python -m pip install 'openstudio-si[plugin-dev]==0.5.1'

Use your organization’s owner ID, maintainer name, and approved license. You can export the generated starter immediately. Use --with-mcp when scaffolding a plugin that needs an MCP server.

openstudio-si plugin check-project .
openstudio-si plugin validate ./plugin
mkdir -p dist
openstudio-si plugin export ./plugin --host all --output ./dist/starter \
  > dist/starter-report.json

Continue with the OSM walkthrough to replace the starter with a working model summary.

What OpenStudio SI core offers

Orchestration and providers
Route modeling requests to the right workflow or execution provider, including NLR OpenStudio-MCP when configured and compatible.
Workflow state and artifacts
Track sessions, model lineage, assumptions, outputs, and results across modeling steps.
Setup and readiness
Set up and diagnose the core runtime. Developer tooling also inspects declared plugin prerequisites and capability readiness.
Simulation and results
Launch simulations, collect artifacts, and query results through the core MCP runtime.

Install the core host plugin for capabilities that use these services. For example, HVAC Modeler owns its HVAC skills and requires compatible core. Its local inspection and editing checks can use core metadata on disk. Simulation and results require a live core runtime. The OSM example relies only on the OpenStudio Python SDK.

The PyPI extra openstudio-si[plugin-dev] provides the developer CLI. See Installation to enable core in a host.

Project layout

my-plugin/
  AGENTS.md, CLAUDE.md         Contributor guidance
  .github/workflows/           Validation and release stubs
  plugin/
    openstudio-si-plugin.yaml  Identity, dependencies, and capabilities
    skills/<skill>/SKILL.md    Agent instructions
    skills/<skill>/scripts/    Skill-local executable helpers
    .mcp.json                  Optional MCP server configurations
    evals/cases/               Evaluation cases
  dist/                        Local host exports and release assets

Keep authored source in plugin/. Exports generate the Claude and Codex metadata from the same source. Declare additional package resources with package.include and use paths relative to the plugin root.

For an existing repository, scaffold into a temporary project and bring over the plugin manifest, desired skill layout, and workflow stubs. Keep the existing license and set the manifest and reusable workflows for the actual source repository.

CLI reference

The reference below shows command usage and flags from version 0.5.1. Expand a command for its arguments.

  destination

Plugin specifications

Manifest fieldContract
schema_versionRequired. Use draft version "0.1".
id, name, description, versionRequired. Use a lowercase hyphenated ID and a SemVer release version. openstudio-si and openstudio-si-hvac are reserved IDs.
owner, license, contributorsOwner and license are required. Record the owner ID and maintainers. Contributors are optional.
compatibility.harness_apiRequired. The 0.5.1 tooling implements harness API 0.1.0. Declare a range compatible with that API. This is separate from the core plugin version.
dependenciesRequired list. Each entry has an ID, kind, target, required flag, and probe. Use an empty list when there are no dependencies.
capabilitiesRequired. Describe at least one capability and reference dependency IDs in its requires list.
evaluation.casesRequired path to evaluation cases inside the source plugin.
inventory, package.includeOptional. Export discovers skill and MCP counts. Use include paths for extra resources.

Dependencies and readiness

Supported dependency kinds are plugin, Python distribution, command, MCP server, dataset, and configuration. Python requirements use PEP 440, such as ==3.11.0. Plugin ranges use space-separated SemVer comparisons, such as >=0.5.0 <0.6.0. An MCP dependency can reference the ID of its declared provider plugin.

Doctor can report ready, unavailable, or unknown. A metadata check establishes what it can observe about declarations and prerequisites. Check the report’s evidence for runtime probes, and verify actual enablement in the host. Runtime probes are opt-in and require an explicit profile.

Walkthrough · Summarize an OSM model

Start with the osm-model-summary project from the quickstart. This example reports stories, spaces, zones, and HVAC inventory from a local OpenStudio model. It uses one skill and zero MCP servers.

Add the skill and script

mv plugin/skills/osm-model-summary plugin/skills/summarize-osm
mkdir -p plugin/skills/summarize-osm/scripts

Replace plugin/skills/summarize-osm/SKILL.md with the following.

---
name: summarize-osm
description: Inspect a local OpenStudio OSM and report model inventory without editing or simulating it.
---

Use this skill when the user asks what an OSM contains or requests a model summary.

1. Identify the exact input .osm. If several files could be intended, ask which.
2. Use the Python environment selected for this plugin. Run the bundled
   `scripts/summarize_osm.py` with the model path as a quoted positional argument.
   Resolve the script relative to this SKILL.md; do not depend on a developer's
   checkout path or write a replacement script.
3. If the SDK is unavailable or loading fails, report the error and the required
   SDK/environment. Do not treat a missing dependency as proof the model is corrupt.
   Invalid inputs may produce native SDK diagnostics despite logger suppression;
   treat exit code 2 as failure and do not try to parse that output as summary JSON.

"""Summarize an OSM without editing, saving or simulating it."""

import argparse
import hashlib
import json
import sys
from pathlib import Path


def summarize(path):
    import openstudio

    if openstudio.openStudioVersion() != "3.11.0":
        raise ValueError("This plugin requires OpenStudio SDK 3.11.0.")
    path = path.expanduser().resolve(strict=True)
    if not path.is_file() or path.suffix.lower() != ".osm":
        raise ValueError("Select an existing .osm file.")
    before = hashlib.sha256(path.read_bytes()).hexdigest()
    openstudio.Logger.instance().standardOutLogger().disable()
    translator = openstudio.osversion.VersionTranslator()
    loaded = translator.loadModel(openstudio.path(str(path)))
    if not loaded.is_initialized():
        raise ValueError("The selected SDK could not load this model.")
    model = loaded.get()
    spaces = sorted(model.getSpaces(), key=lambda item: item.nameString())
    zones = sorted(model.getThermalZones(), key=lambda item: item.nameString())
    air_loops = sorted(model.getAirLoopHVACs(), key=lambda item: item.nameString())
    unassigned = [space.nameString() for space in spaces if not space.thermalZone().is_initialized()]
    warnings = []
    if not spaces:
        warnings.append("The model contains no spaces.")
    if unassigned:
        warnings.append("Some spaces are not assigned to thermal zones.")
    if not air_loops:
        warnings.append("No air loops were found; zone HVAC equipment may still exist.")
    if hashlib.sha256(path.read_bytes()).hexdigest() != before:
        raise ValueError("The input changed during inspection; rerun on a stable file.")
    return {
        "format": "openstudio-si-osm-summary/0.1",
        "input_name": path.name,
        "input_sha256": before,
        "sdk_version": openstudio.openStudioVersion(),
        "building_name": model.getBuilding().nameString(),
        "counts": {
            "stories": len(model.getBuildingStorys()),
            "spaces": len(spaces),
            "thermal_zones": len(zones),
            "air_loops": len(air_loops),
            "plant_loops": len(model.getPlantLoops()),
            "zone_hvac_equipment": sum(len(zone.equipment()) for zone in zones),
        },
        "spaces": [
            {"name": space.nameString(), "floor_area_m2": space.floorArea(),
             "thermal_zone": space.thermalZone().get().nameString() if space.thermalZone().is_initialized() else None}
            for space in spaces
        ],
        "zones": [zone.nameString() for zone in zones],
        "air_loops": [
            {"name": loop.nameString(), "served_zones": sorted(zone.nameString() for zone in loop.thermalZones())}
            for loop in air_loops
        ],
        "plant_loops": sorted(loop.nameString() for loop in model.getPlantLoops()),
        "unassigned_spaces": unassigned,
        "warnings": warnings,
        "simulation_performed": False,
    }


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("model", type=Path)
    args = parser.parse_args()
    try:
        result = summarize(args.model)
    except ImportError:
        print("OpenStudio SDK unavailable: select the plugin's Python environment.", file=sys.stderr)
        return 2
    except (OSError, ValueError, RuntimeError) as exc:
        print(str(exc), file=sys.stderr)
        return 2
    print(json.dumps(result, indent=2, allow_nan=False))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
